# Learning Rules

1. One core repository per week during Weeks 1–10.
2. Do not add another core repository before completing the initial ten.
3. Start from architecture and execution paths, not API memorization.
4. Run or trace real code before accepting architectural conclusions.
5. Study failures and maintenance work, not only examples.
6. Every reusable pattern needs evidence and rejection conditions.
7. Record unknowns instead of filling gaps with assumptions.
8. Separate framework knowledge from transferable engineering knowledge.
9. End each week with a decision record and implementation experiment.
10. Prefer depth over volume.

## Time-boxing
If time is constrained, prioritize in this order: architecture docs/source path, representative demo, high-signal Issues/PRs, pattern extraction, secondary content.

## Completion rule
A week can remain incomplete. Do not manufacture conclusions to satisfy the schedule.
